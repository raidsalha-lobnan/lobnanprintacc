# توثيق المزامنة السحابية الشاملة لكامل قاعدة البيانات

## 1. ملخص طلب المستخدم
- طلب المستخدم أن يكون زر المزامنة مخصصاً لنقل **كامل قاعدة البيانات** وليس مقتصراً على الفواتير، بحيث يشمل كل العمليات والمدخلات (العملاء، الأصناف، السندات، المشتريات، المردودات، الخزن، الحسابات، الموظفين، القيود اليومية، إلخ) ومزامنتها لحظياً عبر كافة الشاشات وأجهزة النظام.

## 2. الإجراءات المنفذة
1. **توسيع محرك المزامنة `syncCurrentDataToFirestore`**:
   - تم شمل كافة الجداول والكيانات التشغيلية في النظام (26 كياناً):
     - فواتير المبيعات (`invoices`)
     - العملاء والموردين (`parties`)
     - الأصناف والمخزون (`inventory`)
     - سندات القبض والصرف (`vouchers`)
     - فواتير المشتريات ومردوداتها (`purchases`, `purchaseReturns`)
     - مردودات المبيعات (`salesReturns`)
     - دليل الحسابات والخزن (`accounts`, `treasuries`)
     - القيود اليومية وحركات المخزون والمصروفات (`journalEntries`, `stockMovements`, `expenses`)
     - الموظفين، السلف، الخصومات، الحوافز، ومسيرات الرواتب (`employees`, `employeeAdvances`, `employeeDeductions`, `employeeIncentives`, `payrollSheets`)
     - طلبات الطباعة ومقاصات الديون (`printOrders`, `debtClearings`)
     - الشركات، الفروع، والمستودعات وعملياتها (`companies`, `branches`, `warehouses`, `warehouseOperations`)
     - المستخدمين والصلاحيات (`users`, `roles`)
     - شيت القيود اليومية السريعة (`dailyEntrySheets`)
     - إعدادات النظام العامة (`settings`)
   - الرفع يتم عبر دفعات معزولة (`writeBatch`) لا تتجاوز 250 عملية لكل دفعة، مع تنظيف الرموز وتفادي حدود Firestore.
   - حساب إجمالي السجلات عبر كافة الجداول وعرض تقرير تفصيلي بالعمليات المنقولة.

2. **توسيع المعالج السحابي في السيرفر `/api/sync/replace-database`**:
   - تعديل مسار السيرفر في `vite.config.ts` ليمر على كافة الجداول من `ALL_SYNC_ENTITIES` وحفظها في Firestore وملفات الذاكرة المؤقتة السحابية.

3. **المزامنة اللحظية الحية (`onSnapshot`) لكافة الشاشات**:
   - ربط مستمعات حية فورية للعمليات والكيانات لضمان ظهور أي تعديل أو إدخال جديد على أي شاشة لدى باقي الأجهزة فوراً.

4. **تحديث واجهة المستخدم (زر المزامنة في الإعدادات)**:
   - تم تعديل زر المزامنة ليظهر إجمالي عدد السجلات الكلية لكامل قاعدة البيانات بصيغة:
     `مزامنة كامل قاعدة البيانات (X سجل) مع السحابة فوراً ☁️`
   - عند الضغط على الزر، يظهر كشف كامل ومفصل بكافة السجلات التي تم رفعها وتثبيتها سحابياً.

## 5. خوارزمية حسم تصادم أرقام الفواتير عند المزامنة (Invoice Number Collision Resolution)
1. **تشخيص المشكلة في الصورة المرفقة**:
   - أظهرت الصورة وجود فاتورتين بنفس الرقم **`INV-0001`** (الأولى بتاريخ 01/11/2026 بمبلغ 5 شيكل لعميل زبون نقدي، والثانية بتاريخ 03/11/2026 بمبلغ 66 شيكل لمؤسسة مؤاخاة).
2. **السبب الجذري**:
   - الفاتورتان تم إنشاؤهما على جهازين منفصلين دون اتصال بالشبكة، وأعطى كل جهاز محلياً الرقم `INV-0001` للفاتورة الأولى لديه.
   - عند المزامنة، كانت الدالة السابقة تقوم بتعيين الأرقام تسلسلياً حسب الفهرس دون فحص تاريخ ووقت الإنشاء الدقيق، مما أبقى على أرقام متصادمة في القائمة المباشرة.
3. **الحل الذكي المطبق**:
   - عند المزامنة واكتشاف فاتورتين بنفس الرقم (`INV-0001`) عبر جهازين، يتم فحص **الطابع الزمني الدقيق للإنشاء (`createdAt` / `date`)**:
     - الفاتورة **الأقدم تاريخاً ووقتاً** (01/11/2026) تحتفظ بـ **`INV-0001`**.
     - الفاتورة **الأحدث تاريخاً ووقتاً** (03/11/2026) يتم تصحيح ترقيمها أوتوماتيكياً لأقرب رقم تسلسلي فريد متاح (مثل **`INV-0002`** أو التالي المتاح).
   - تم دمج هذه الخوارزمية مباشرة في مستمع المزامنة اللحظي (`onSnapshot`) في `AccountingContext.tsx` لمنع ظهور أي رقمين متطابقين للفواتير على أي شاشة نهائياً.
